# 文件系统规划(草案,随实现迭代)

原则:**所有状态都在文件系统里**——纯文件、可 ls、可 git、可 rm 重来,没有数据库没有隐藏状态。
agent 无记忆,进来先看目录就知道世界现状;`drawtell ls` 只是把这套目录读给你看。

## 两个根:工具 与 工作区

| | 位置 | 内容 | 公私 |
|---|---|---|---|
| 工具 | drawtell 检出/安装目录 | 代码、`dist/web`(播放页构建产物)、`scenes/`(种子场景 = 示例 + 打磨台内置 + 测试夹具) | 公开仓 |
| 工作区 | 解析优先级:全局 `--workspace <dir>` > cwd 有 `drawtell.json` > `~/.config/drawtell/config.json` 的 `workspace` > cwd 兜底 | 家庭内容与状态(下详) | 私有,建议独立 git 仓 |

`--workspace` 决定工作区与 `paths` 落点;场景位置参数(`<scene.ts>`)与 `--out`、`--bundles`
的相对路径仍按 cwd 解析。每条 `--json` 都回报解析到了哪个工作区
(`workspaceSource`:`flag` / `cwd` / `user-config` / `default`)。
CLI 约定:静态资源永远取自工具侧;`scenes/` 相对工作区,`bundles/`、`snaps/` 相对**派生根**
(缺省即工作区,由 `drawtell.json` 的 `paths` 段改;`--out`、`--bundles` 优先级最高)。
种子场景在工具仓里"自己当自己的工作区"。
家庭真题**不进公开的 drawtell 仓**,放私有工作区(第一道真题落地时建仓)。

## 工作区布局

```
<workspace>/                工作区只留「源」与「人的决定」——不可再生的一切
├── scenes/<id>.ts          源:场景 TS,唯一手写(或 agent 写)的层
├── <reviews>/<id>.md       ★ 不可再生:家长验收记录(frontmatter 记 验收 / manifestHash / 日期,
│                             正文写评语)。它同时就是"做过哪些课包"的人读索引。<reviews> 是目录角色,
│                             缺省 reviews/,由 drawtell.json 的 paths.reviews 改(如中文 课包/)
├── tidy-log.md             ★ 不可再生:tidy --delete 的删除清单(人的决定:答得出"那张图哪去了")
└── drawtell.json           政策(dub 音色、title 孩子端标题)+ paths(派生物往哪写 + 家长面目录角色)

<派生根>/                    默认 <workspace>/,可由 drawtell.json 的 paths 段指到缓存目录
├── bundles/<id>/           课包:自包含目录,iPad 整目录下载
│   ├── scene.json          派生:build 幂等再生
│   ├── manifest.json       派生:build 幂等再生
│   └── audio/              TTS 预合成:派生但贵(由 voxtell 用户级缓存回填,见下)
└── snaps/<id>/             纯缓存:keyframe 截图 + index.json,随时可删,snap 再生
```

**为什么把派生根拆出去**:这样工作区本身只剩不可再生的东西,可以整个当笔记库(Obsidian vault)用、
整个进 git、整个备份,不必在 16M+ 的 build 产物里挑。`paths` 缺省仍是工作区下的 `bundles/`、`snaps/`,
不破坏任何已有工作区:

```json
{ "title": "…",
  "paths": { "bundles": "~/.cache/drawtell/<ws>/bundles", "snaps": "~/.cache/drawtell/<ws>/snaps", "reviews": "课包" },
  "dub": { "voice": "…" } }
```

**验收记录必须在工作区侧,不能在派生根里**——它不可再生,而派生根是随时可 `rm -rf` 的。
早先把 `review.json` 放在 `bundles/<id>/` 是个隐患:一句 rm 就把家长的验收全清了。

## 目录角色与 title

工作区里**家长面**的目录(验收、作业原图、收件箱、错题账本、家长参考、孩子页)在所有契约与 skill 里**只用英文角色名**,
实际目录由 `drawtell.json` 的 `paths` 段决定,缺省同名英文目录——契约面是英文的,中文目录是某个家的配置;
家长想叫什么都行,改一行映射,不改任何文档。`paths.bundles`、`paths.snaps` 是同一机制的派生物用法。

| 角色 | 缺省目录 | 谁读写 | 四类 |
|---|---|---|---|
| `reviews` | `reviews/` | `drawtell ls` 读(验收态);serve 验收页写 | 人的决定 |
| `photos` | `photos/` | homework skills | 源 |
| `ledger` | `ledger/` | homework skills | 人的决定 |
| `notes` | `notes/` | skills 读(家长的口径) | 人的决定 |
| `kids` | `kids/` | skills / Obsidian | 人的决定 |
| `inbox` | `inbox/` | homework skills(作业照片进件);CLI 不读不写,归 skills 与应用层 | 源 |

另:`timetable` 是**应用层角色**——apps/web 读工作区 `drawtell.json` 的 `paths.timetable` 定位
课程表文件;CLI 不认识该角色(`paths` 里的未知键无害,原样忽略,不解析不回报)。

CLI 只读 `reviews`;其余角色它只解析出来(`--json` 回报),不读不写。
`title` 是孩子端界面标题,缺省 `drawtell`:**孩子端没有品牌**,名字是家长的配置。消费方是 serve 的课包清单页(`/` 无参,iPad 入口)
与应用层页面(朗读书架),都经 `GET /api/config` 读;打磨台(`&bench=1`)不用它。

## 状态分类(规划的主轴:丢了怎么办)

| 类别 | 例子 | 丢了怎样 | git |
|---|---|---|---|
| 源 | `scenes/*.ts` | 不可再生 | ✓ |
| 人的决定 | `<reviews>/<id>.md` 的验收与评语 | 不可再生(验收是人做的) | ✓ |
| 贵派生 | `bundles/*/audio/`(+ 语音 CLI 的用户级缓存) | 可再生,但花钱耗时 | ✗ |
| 廉派生 | `bundles/*/{scene,manifest}.json`、`snaps/` | 秒级再生 | ✗ |

判断一个新文件放哪,先问它属于哪一类。

## 幂等与新鲜度

- **build 只写 scene.json / manifest.json**,不碰 `<reviews>/<id>.md` 与 audio/ ——
  重建永远不会误删人的决定和贵产物(现有实现已如此)。
- **产物文件里不放时间戳**:幂等 = 同输入字节一致;builtAt 之类易变元数据不进课包。
- **验收绑内容而不是绑目录**:`<reviews>/<id>.md` 的 frontmatter 记 `manifestHash`(sceneHash 暂不记:目前无人读写);
  场景改了重新 build,hash 对不上 = 验收自动失效,`ls` 应显示"已改动,需重验"。
  它由家长验收动作写入(将来 serve 的验收页,或手工),CLI 的 build/snap 不生成它;
  **机器只改 frontmatter,不动正文**——正文是家长的评语。
- snaps 新鲜度同理:index.json 里加 manifestHash(待实现),不符即过期。

## TTS 音频(`drawtell dub`,2026-08 落地)

- 合成与内容寻址缓存归**独立的语音 CLI** voxtell(用户级 `~/.cache/voxtell/`,跨工作区共享)。
- drawtell 侧只做粘合:manifest 各步 line → `voxtell batch` → 拷进课包 `audio/step-<n>.mp3` →
  写 `audio/index.json`(步 ↔ 文件 ↔ 讲稿 hash ↔ 音色 ↔ 时长)→ 回填 audioSrc 与 audioDurationMs
  (播放器据此把该步笔画拉伸到讲稿长度;dub 会报每步 音/画/拉伸倍数,超 5 倍是讲法问题)。
- 课包必须自包含(iPad 整目录下载、离线播放),所以 audio/ 是**缓存回填的拷贝**,不是引用。
- 改一句讲稿只重合成那一句——缓存 key 按步的文本算,不按整包算;`build` 只回填讲稿 hash 仍匹配的步,
  改过的步失去音频直到重新 dub。
- 音色/语气是政策:工作区根 `drawtell.json` 的 `dub` 段(`voice` / `instruction` / `model`),
  或命令行 `--voice`;没有默认音色。`audio/jobs.json`、`results.json` 是 voxtell 的进出清单(廉派生)。

## 边界

工作区是**所有 drawtell 子产品**(homework 作业 / reading 朗读 / canvas 画板;只有 drawtell 一个品牌,子产品名是描述家庭场景
的普通名词,加一个子产品 = 加一个工作流 skill + 一个工作区目录)的家庭内容根。drawtell CLI 只认识其中 `scenes/`、`bundles/`、`snaps/`、
`<reviews>/`、`drawtell.json`;其余目录(`homework/`、`books/`、`captures/`、`problems/`、`<inbox>/`、`<photos>/`、`<ledger>/`…)
由 skills 与应用层定义,按同一张四类表归位,CLI 不读不写(`tidy` 除外——它只按可达性与年龄算,不认识目录含义;
`<inbox>/` 同 `<photos>/` 一样已是 CLI 解析并回报的目录角色,但读写仍归 skills 与应用层)。

- `dist/web`、`public/fonts`:工具侧构建产物,不在工作区。
- 孩子的墨迹 / 录音 / 朗读会话:画板与朗读子产品的数据,进工作区(或家庭指定的私有根),按四类表归位;CLI 不认识它们。
- 错题状态机(错→讲过→隔日对→结清):作业子产品的状态,在 `<ledger>/` 里;课包目录只被它引用,不反向存它的状态。
